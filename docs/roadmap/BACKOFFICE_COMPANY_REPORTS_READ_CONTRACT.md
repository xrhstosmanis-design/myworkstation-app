## Scope and admission

The real Owner reports support company-wide reads, with optional store filters. Price history even includes company-global storeId=null rows when a store is selected. These cannot silently become a STORE-only permission. Proposed independent COMPANY report rights explicitly grant company-wide financial/audit information; a STORE grant alone never authorizes them. They require actual installed COMPANY authority, live account/policy revision and company license plus INVENTORY, matching native `/api/reports` mounts for these four readers. No invented extra CORE/CASH module or personal store membership is required. Existing COMPANY policies omit new keys by default.

Use the exact company-header bridge BEFORE kioskReportsPosSaleActionsRoutes and kioskReportsAuditRoutes. Native report routers have role checks, and the audit router runs ensureKioskReportAuditSchema for every route, so forwarding a delegated GET through the generic `/api/reports` stack is forbidden. Keep Owner paths unchanged. Dedicated SQL projections perform no DDL/bootstrap/reconciliation/provider/file/export/writer work and never impersonate Owner.

Strict query: mandatory single actual Greece calendar from/to; optional single trimmed q<=120 only where native uses it; optional single owned active storeId for an explicitly supported filter. Reject duplicate/array/unknown keys, malformed calendars, reversed ranges, GET bodies and mixed company/store headers. Use Greece inclusive day-start to exclusive next-day endpoint, not host-local Date construction. Filters are values bound in tagged queries. No full company selector API is implicitly opened by mounting the report suite. A first UI can offer only the date/search controls and truthful all-company scope; adding store-picker data later requires an explicit reviewed selector contract.
