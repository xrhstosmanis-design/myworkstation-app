# MyWorkStation — Permanent Project Handoff

Αυτό το αρχείο είναι το μόνιμο σημείο συνέχειας του έργου. Κάθε νέα εργασία, αλλαγή, απόφαση ή ολοκληρωμένο στάδιο πρέπει να αποθηκεύεται άμεσα στο repository ώστε οποιαδήποτε επόμενη συνεδρία GPT να μπορεί να συνεχίσει χωρίς να ξαναστήνει ή να ξαναμαντεύει το έργο.

## Απαράβατος κανόνας

1. Δεν βασιζόμαστε στη μνήμη της συνομιλίας ή στη σελίδα του browser.
2. Κάθε ουσιαστική αλλαγή κώδικα αποθηκεύεται αμέσως σε branch/commit.
3. Κάθε σημαντική απόφαση αρχιτεκτονικής ή λειτουργίας καταγράφεται αμέσως σε docs μέσα στο repository.
4. Κάθε ενεργή φάση εργασίας πρέπει να έχει σαφές branch και, όπου υπάρχει, PR.
5. Πριν κλείσει μια φάση, ενημερώνεται αυτό το handoff με: τι ολοκληρώθηκε, τι είναι ενεργό, τι απομένει, ποιο branch/PR συνεχίζει.
6. Καμία νέα συνεδρία δεν ξαναφτιάχνει λειτουργίες που υπάρχουν ήδη. Πρώτα διαβάζει αυτό το αρχείο, το `docs/TEST_POS_FUNCTIONAL_BASELINE.md`, το ενεργό PR και το σχετικό branch.
7. Το TEST είναι η μόνιμη βάση ανάπτυξης. Δεν υπάρχει πραγματικό κατάστημα ΚΑΤ ως πηγή.

## Σταθερό μοντέλο δοκιμών

- SUPER ADMIN = ο ιδιοκτήτης/διαχειριστής της πλατφόρμας.
- ADMIN = ο ιδιοκτήτης του καταστήματος.
- POS = το POS του καταστήματος / καθημερινή ροή πωλητή.

Κάθε λειτουργία θεωρείται ολοκληρωμένη μόνο όταν ελέγχεται σωστά και στους τρεις ρόλους όπου εφαρμόζεται.

## Τρέχουσα κατάσταση

- Μόνιμη βάση ανάπτυξης: `TEST`.
- Ενεργό branch: `feat/test-three-role-baseline`.
- Ενεργό PR: `#80` — `TEST POS: επαναφορά πλήρων τρόπων πληρωμής και μόνιμο functional baseline`.
- Το PR #79 έχει ήδη γίνει merge στο `main` και καθιέρωσε το TEST ως μόνιμη βάση ανάπτυξης.
- Υπάρχει μόνιμο POS functional baseline στο `docs/TEST_POS_FUNCTIONAL_BASELINE.md`.
- Το TEST POS πρέπει να διατηρεί όσα έχουν ήδη υλοποιηθεί και να συμπληρώνεται πάνω στην ίδια βάση, όχι να αντικαθίσταται.

## Ολοκληρώθηκε στο τρέχον PR

- Backend τρόποι πληρωμής: CASH, CARD, IRIS, MIXED.
- Έλεγχος ότι η μικτή πληρωμή ισούται ακριβώς με το σύνολο.
- Barcode / αναζήτηση προϊόντος στο TEST POS από barcode, SKU ή όνομα.
- Πεδία ΕΛΑΒΑ / ΡΕΣΤΑ με αριθμητικό πληκτρολόγιο.
- Επιλογή γραμμής συναλλαγής.
- Αύξηση / μείωση ποσότητας και ορισμός ποσότητας μέσω πλήκτρου ΠΟΣ.
- Διαγραφή επιλεγμένης γραμμής.
- Payment panel με Μετρητά / Κάρτα / IRIS / Μικτή.
- Βασική Αναμονή συναλλαγής και επαναφορά της.
- Όλες οι παραπάνω αλλαγές έχουν αποθηκευτεί άμεσα σε commits στο ενεργό branch.

## Άμεση συνέχεια εργασίας POS

Στο ίδιο branch/PR συνεχίζουμε με:

- μεταφορά της Αναμονής από προσωρινή local κατάσταση σε server-side store/session κατάσταση,
- πλήρες panel `ΠΛΗΡΩΜΕΣ`,
- Μεταφορά ποσού,
- Πληρωμή προμηθευτή,
- Λοιπά έξοδα,
- Οι πληρωμές μου,
- κλείσιμο βάρδιας και έλεγχος POS/EFTPOS,
- πλήρη έλεγχο 3 ρόλων,
- CI/build έλεγχο πριν από merge.

## Υποχρεωτική διαδικασία για κάθε επόμενη συνεδρία GPT

Πριν κάνει οποιαδήποτε αλλαγή:

1. Διάβασε `docs/PROJECT_HANDOFF.md`.
2. Διάβασε `docs/TEST_POS_FUNCTIONAL_BASELINE.md`.
3. Έλεγξε το ενεργό branch και το ενεργό PR.
4. Συνέχισε από το τελευταίο commit χωρίς επανεκκίνηση του σχεδιασμού.
5. Μετά από κάθε ουσιαστική αλλαγή, κάνε commit άμεσα και ενημέρωσε αυτό το handoff αν αλλάζει η κατάσταση του έργου.

Αυτός ο κανόνας υπερισχύει οποιασδήποτε παλιότερης ροής που βασιζόταν σε προσωρινή κατάσταση, browser state ή μνήμη συνομιλίας.
