# TEST POS — Permanent Functional Baseline

Αυτό το αρχείο είναι η μόνιμη λίστα αναφοράς για το POS του TEST. Δεν ξανασχεδιάζουμε το POS από την αρχή. Κάθε νέα αλλαγή πρέπει να ελέγχεται απέναντι σε αυτή τη λίστα και να διατηρεί τις ήδη ολοκληρωμένες λειτουργίες.

## 1. Βασική ροή πωλητή

- Προσωπική είσοδος πωλητή με PIN και, όπου ενεργοποιηθεί, προσωπική κάρτα.
- Ονομαστικό audit για τον συνδεδεμένο πωλητή.
- Υποχρεωτικό άνοιγμα ταμείου/βάρδιας πριν επιτραπεί πώληση.
- Πεδία ανοίγματος: Συρτάρι, Φύλαξη, Κέρματα, Χρηματοκιβώτιο.
- Κανονική έξοδος/logout από το POS χωρίς να χάνεται η μόνιμη κατάσταση TEST.

## 2. Κύρια οθόνη POS

- Πλήρης Store POS οθόνη, όχι Store Mode/Backoffice.
- Header με κατάστημα, συνδεδεμένο χρήστη και κατάσταση ταμείου.
- Barcode scanner / αναζήτηση προϊόντος.
- Γρήγορα προϊόντα (quick keys).
- Κατηγορίες προϊόντων.
- Πλέγμα προϊόντων με τιμή και, όπου έχει οριστεί, SKU/stock.
- Καλάθι/γραμμές συναλλαγής με ποσότητα, είδος, τιμή και σύνολο γραμμής.
- Συνολικό ποσό συναλλαγής ευδιάκριτα δεξιά.
- Αριθμητικό πληκτρολόγιο.
- Πεδία «Έλαβα» και «Ρέστα».
- Τα γρήγορα/λειτουργικά πλήκτρα να είναι οριζόντια όπου έχει ζητηθεί.

## 3. Διαχείριση καλαθιού

- Αύξηση/μείωση ποσότητας.
- Πλήκτρο ΠΟΣ. για αλλαγή ποσότητας.
- ΑΛΛΑΓΗ γραμμής/είδους όπου υποστηρίζεται.
- ΣΒΗΣΙΜΟ επιλεγμένης γραμμής.
- ΑΚΥΡΩΣΗ / καθαρισμός ολόκληρης τρέχουσας συναλλαγής.
- ΚΑΘΑΡΙΣΜΟΣ ΠΟΣΟΥ στο αριθμητικό πεδίο.
- Υποστήριξη αναμονής συναλλαγής (ΑΝΑΜΟΝΗ) ως καθορισμένη POS ενέργεια.

## 4. Κάτω λειτουργικά πλήκτρα που έχουν οριστεί

- ΑΚΥΡΩΣΗ — CLEAR_CART.
- ΕΚΤΥΠΩΣΗ — PRINT.
- ΑΝΑΜΟΝΗ — HOLD.
- ΠΛΗΡΩΜΕΣ — PAYMENTS.
- ΕΣΩΤΕΡΙΚΗ — INTERNAL.
- ΚΟΥΒΑΣ — WASTE.
- ΜΕΤΡΗΤΑ — CASH.
- IRIS — IRIS.
- ΜΙΚΤΗ — MIXED.
- ΚΑΡΤΑ — CARD.

Τα παραπάνω πλήκτρα, η σειρά, τα χρώματα και η ορατότητά τους διαχειρίζονται από τον POS Designer του Super Admin και δημοσιεύονται στο POS.

## 5. Τρόποι πληρωμής / ολοκλήρωση

- Μετρητά.
- Κάρτα.
- IRIS ως ξεχωριστή επιλογή.
- Μικτή πληρωμή ως ξεχωριστή επιλογή.
- Η πληρωμή πρέπει να συνδέεται με την ενεργή βάρδια και τον συνδεδεμένο πωλητή.
- Στο TEST η φορολογική εκτέλεση παραμένει απενεργοποιημένη μέχρι να συνδεθεί πιστοποιημένος connector/ταμειακή.

## 6. POS Designer / Super Admin

- Κεντρικός σχεδιαστής POS μόνο για Super Admin.
- Επεξεργασία quick keys.
- Επεξεργασία κατηγοριών.
- Επεξεργασία κάτω πλήκτρων.
- Αλλαγή χρωμάτων.
- Αλλαγή σειράς.
- Ρύθμιση αριθμού στηλών προϊόντων.
- Εμφάνιση/απόκρυψη SKU.
- Πρόχειρο layout πριν από δημοσίευση.
- Ρητή δημοσίευση της έκδοσης του POS.
- Το Store POS διαβάζει μόνο το δημοσιευμένο layout του δικού του store.

## 7. Προϊόντα / τιμές / barcode

- Προϊόντα και κατηγορίες από την ενιαία εμπορική βάση.
- Barcode ανά προϊόν.
- Τιμή πώλησης ανά κατάστημα.
- Stock/διαθεσιμότητα ανά κατάστημα.
- Quick key που αντιστοιχεί σε συγκεκριμένο προϊόν.
- Απομακρυσμένη διαχείριση προϊόντων/τιμών από Super Admin και, ανά δικαιώματα, από Admin.

## 8. Συναλλαγές καταστήματος που πρέπει να παραμείνουν στη συνολική POS/Store ροή

- Μεταφορά ποσού.
- Πληρωμή προμηθευτή.
- Λοιπά έξοδα.
- «Οι πληρωμές μου» / ιστορικό πληρωμών.

Αυτές οι λειτουργίες δεν πρέπει να χαθούν όταν ενοποιείται η καθημερινή λειτουργία του πωλητή. Μπορούν να είναι σε ξεχωριστό panel/menu του POS ώστε να μη φορτώνουν την κύρια οθόνη πώλησης.

## 9. Βάρδια / ταμείο / έλεγχος

- Άνοιγμα βάρδιας πριν από πώληση.
- Κλείσιμο βάρδιας με Συρτάρι, Φύλαξη, Κέρματα και Χρηματοκιβώτιο.
- Επόμενη έναρξη = Συρτάρι + Φύλαξη + Κέρματα.
- Καταγραφή POS και EFTPOS για έλεγχο στο κλείσιμο.
- Προειδοποίηση σε απόκλιση POS/EFTPOS, χωρίς αυτόματη ακύρωση πώλησης.
- Αναφορά/ιστορικό βάρδιας και συναλλαγών.

## 10. Κανόνας ανάπτυξης

Κάθε αλλαγή στο TEST POS πρέπει να ελέγχεται σε τρεις ρόλους:

1. Super Admin — σχεδιασμός, προϊόντα, ρυθμίσεις, δημοσίευση και έλεγχος.
2. Admin/Ιδιοκτήτης — διαχείριση της δικής του επιχείρησης και καταστήματος.
3. POS/Πωλητής — πραγματική καθημερινή ροή πώλησης.

Δεν διαγράφουμε ή ξαναφτιάχνουμε από την αρχή υπάρχον layout, προϊόντα, κατηγορίες, barcodes, τιμές ή ρυθμίσεις TEST. Πριν από σημαντικές αλλαγές χρησιμοποιείται server-side TEST snapshot/checkpoint.

## Πηγή / ιστορικό

Η λίστα συγκεντρώνει τις λειτουργίες που υπάρχουν στο repository history και τις σταθερές POS απαιτήσεις του project. Οι λειτουργίες που υπάρχουν μόνο ως καθορισμένη ενέργεια αλλά δεν έχουν ακόμη πλήρη backend εκτέλεση πρέπει να ολοκληρωθούν πάνω στην ίδια οθόνη και όχι να αντικατασταθούν με νέο POS.
