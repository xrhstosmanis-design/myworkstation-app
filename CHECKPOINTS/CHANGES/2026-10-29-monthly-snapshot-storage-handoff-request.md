## Two phases, because the source transaction is actually READ ONLY

1. A bounded consistent source read uses ONE actual READ ONLY Repeatable Read/Serializable transaction. Read current generation/maintenance/retired state without enrollment/ensure/DDL; authorize the selected personal/current role/company/store/module under the C2 contract; read complete stock and C2 invoice/pending metadata through that SAME transaction; record database read times at entry/end. No INSERT is attempted in this transaction. C2's fixed30-second admission and truthful held-snapshot authorization label remain protected.
2. After the read transaction closes, a separate trusted write transaction rechecks current authorization/license/store state and the exact lifecycle generation/maintenance/retired conditions, using the retained owner's reviewed fence/CAS/lock protocol. It verifies that the candidate and admission scope/generation/version/hash/count fields agree before the immutable insert. A reset, retirement, maintenance transition or generation change between phases refuses persistence. Absence/enrollment races require the owner's explicit protocol; absence returning generation0 is not a lock or automatic enrollment.

Future D2 due admission must gate the actual consistent source transaction, not merely a later sourceObservedAt/readFinishedAt value accepted by D1. Conservatively require the database-derived transactionStartedAt >= scheduledFor, together with the bounded entry/exit admission, before accepting a monthly source observation. An RR transaction opened at06:59:59 and finished at07:00:01 must be refused for the07:00 slot because its held view can contain pre-due stock. Never relabel its finish time as proof of a post-due source snapshot, and never call transaction start the exact MVCC acquisition/commit cutoff. This is a proposed future D2 coordinator admission rule; the standalone C2 reader and its current contract remain unchanged.

No new dedicated mutex can be assumed to protect against lifecycle reset unless the lifecycle executor participates in that same reviewed protocol. A READ ONLY transaction cannot take the ordinary mutation/fence write path or SELECT FOR SHARE to conceal the two-phase boundary. Store read observation and storedAt separately. Ordinary source changes after observation can be historical facts only when honestly labelled with the read interval; they must not be claimed current at write time. The proposed mechanism does not reconstruct inventory as of an earlier exact clock instant.
