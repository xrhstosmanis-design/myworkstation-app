## Αιτία

Η server-side ανάγνωση είχε βρει την τυπωμένη καθαρή αξία, αλλά η οθόνη
υπολόγιζε ξανά κάθε γραμμή από `ποσότητα × τιμή × έκπτωση %`. Ακόμη και μετά
τη server διόρθωση, η client οθόνη αντικαθιστούσε μια
`supplierProfileRecovered` ποσότητα με `καθαρή αξία ÷ τιμή`. Επιπλέον, μία
φυσική γραμμή της δεύτερης σελίδας επιστράφηκε από Azure σε visual reading
order αντί για column order.

## Bounded αλλαγή

- Η τυπωμένη καθαρή αξία παραμένει authoritative όταν προέρχεται από την
  επαληθευμένη τρέχουσα εικόνα.
- Η client οθόνη διατηρεί αμετάβλητη την ποσότητα όταν ο server έχει σημειώσει
  τη γραμμή ως `supplierProfileRecovered`.
- Χειροκίνητη αλλαγή ποσότητας, τιμής ή εκπτώσεων εξακολουθεί να επανυπολογίζει
  τη γραμμή άμεσα.
- Για το δηλωμένο TALOS suffix απαιτούνται ταυτόχρονα
  `ποσότητα × τιμή = αξία προ έκπτωσης` και
  `αξία προ έκπτωσης − ποσό έκπτωσης = καθαρή αξία`.
- Αν λείπει μόνο η ποσότητα, γίνεται δεκτή μόνο μοναδική ακέραιη τιμή.
- Για Azure reading-order suffix απαιτείται η αποδεδειγμένη σειρά
  `ποσό έκπτωσης → καθαρή → ΦΠΑ → τιμή → προ έκπτωσης` και μοναδική λύση.
  Για τον `4327325` αυτό δίνει μόνο `7 × 0,85 = 5,95` και
  `5,95 − 1,67 = 4,28`, με ΦΠΑ `13%`.
- Στο client γίνεται δεύτερη fail-closed επαλήθευση μόνο για το ΑΦΜ
  `800802293`: η ποσότητα της ωμής TALOS γραμμής υπερισχύει μόνο όταν
  συμφωνούν και οι δύο εξισώσεις. Οι σωστές γραμμές παραμένουν ίδιες και
  κανένας άλλος προμηθευτής δεν επηρεάζεται.

## Προστατευόμενα δεδομένα

Δεν αλλάζει ήδη εκπαιδευμένο τιμολόγιο, supplier mapping, barcode, Master
Catalog σύνδεση ή profile άλλου προμηθευτή. Δεν δημιουργείται πληρωμή, stock
posting, οριστικοποίηση, λογιστική, fiscal ή myDATA κίνηση.
