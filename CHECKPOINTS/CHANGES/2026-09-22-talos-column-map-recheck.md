# TALOS — χάρτης στηλών και ασφαλής επανέλεγχος

## Κατάσταση

**LAB FAIL / LOCAL PASS / AWAITING CI + DEPLOY + LAB.**

Το δισέλιδο TALOS `01T00125909` διαβάστηκε σε 44 γραμμές, αλλά ο αποθηκευμένος
χάρτης στηλών δεν εφαρμοζόταν στην πραγματική επανάληψη. Η ποσότητα της πρώτης

## Αιτία

1. Ο αρχικός διάλογος «Χάρτης στηλών προμηθευτή» αποθήκευε μόνο στο browser,
   παρότι εμφάνιζε μήνυμα κεντρικής αποθήκευσης.
2. Η γενική αποθήκευση workspace θα συγχρόνιζε μαζικά όλα τα browser profiles.
3. Ένα stable cached OCR αποτέλεσμα επέστρεφε χωρίς να ξαναεφαρμόζει τον
   τρέχοντα κεντρικό κανόνα.
4. Η runtime παράκαμπτε τον χειροκίνητο κανόνα όταν ο provider είχε ήδη θέσει
   `sourceColumnMap`, ακόμη κι αν αυτό ήταν μετατοπισμένο.

## Bounded αλλαγή

- Νέο Super Admin endpoint αποθηκεύει μόνο τον χάρτη στηλών του συγκεκριμένου
  προμηθευτή.
- Γίνεται merge πάνω στο υπάρχον profile και διατηρούνται `mappings`, barcodes,
  διορθώσεις γραμμών και όλα τα υπόλοιπα learned στοιχεία.
- Δεν γίνεται bulk sync ή version bump σε άλλον προμηθευτή.
- Και οι δύο client editors χρησιμοποιούν το στοχευμένο endpoint και ξεκινούν
  αυτόματα επανέλεγχο μετά από επιτυχημένη αποθήκευση.
- Το stable cache ξαναπερνά από το τρέχον supplier profile, learned knowledge
  και completeness reconciliation.
- Ο δηλωμένος χάρτης εφαρμόζεται πάνω στην ωμή τρέχουσα γραμμή και παραμένει
  fail-closed. Για TALOS επαληθεύεται η προ-εκπτώσεων αξία `ποσότητα × τιμή`,
  ενώ η καθαρή αξία επιτρέπεται μόνο ως θετική μη αυξανόμενη αξία όταν υπάρχει
  ξεχωριστή στήλη ποσού έκπτωσης που έχει δηλωθεί `IGNORE`.
